## Use from the integration owner

1. Retain a `TargetCapture` alongside each uploaded frame: original frame ID, UTC capture
   timestamp, camera geometry ID, uploaded upright image dimensions/orientation, and
   the crop rectangle in the FULL upright image. Identity crop must be explicitly supplied.
   Apply EXIF orientation and mirroring before cropping. Arbitrary rotated/perspective crops
   are unsupported: do not pretend they are an axis-aligned crop.
2. Decode the full R3 model and selection. Independently classify control safety locally
   using R2's existing `ControlSafety`; unknown safety must never default to ordinary.
   Call `TargetHandoffAdapter.prepare`. It reselects from the complete model, rejects
   unsafe/ambiguous/unlabeled controls and payment screens, checks capture association,
   and maps the box into the original oriented image. The keyword deny list is only an
   additional guard, not a multilingual emergency/payment classifier.
3. R2 passes `handoff.target` into its existing reacquire flow. The old box is only a
   historical search hint. R1 must locate and independently validate the same labeled
   control in a NEW frame, including current screen/panel identity and safety. A kiosk
   transition or uncertain identity requires a new interpretation. Never apply the old
   box to the current depth map or change its frame ID/timestamp to make it fresh.
4. R1 supplies `R1TargetMeasurement` from measured, aligned local camera/depth/hand data.
   Use measured depth, calibrated intrinsics, orientation mapping and camera pose to
   unproject within R1; no depth or transform is generated by R3. Target, hand and depth
   must refer to one frame and coordinate system. This initial boundary conservatively
   requires exact frame and timestamp matches, not a guessed synchronization tolerance.
   `confidence` is the minimum calibrated confidence of all required observations;
   the gate requires >=0.6. R1 may apply a stricter threshold.
5. Evaluate `TargetEvidenceGate` on EVERY update using the local monotonic clock also used
   by `PhysicalEvidence`. The original UTC timestamp is never used for freshness.
   Only `accepted` may proceed to R2's existing evidence/session/request/generation checks
   and R1's guidance scheduler. Acceptance expires with its measurement at 300ms; it is
   not cached authorization. A periodic freshness watchdog is required even if frames stop.
6. BOTH `reacquire` and `rejected`, any thrown preparation error, canceled request, or
   watchdog expiry mean STOP/no guidance immediately. Use R2's existing local stop path
   (generation increment, pending cancellation, ALL_STOP and R1 local spoken stop).
   Reacquire only under the current task generation. R1 may reject acquisition at any time.
   The adapter deliberately has no speech, movement, haptic, or BLE capability.
